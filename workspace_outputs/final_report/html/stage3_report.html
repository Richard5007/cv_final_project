1. 檢測器架構設計與訓練設定

Stage 3 將問題從「整張圖是什麼瑕疵」延伸到「每個瑕疵在哪裡」（Train=1,260 / Validation=270，驗證集共 641 個標註框）。實作時我們先注意到 VOC XML 標註把 rolled_in_scale 寫成帶連字號的 rolled-in_scale，因此在資料讀取與評估器中統一做了名稱正規化。為了比較單階段與雙階段檢測器的差異，我們在相同切分與 seed=42 下訓練了三組模型：

  • YOLO11s 與 YOLO11m（單階段 Anchor-free）：使用 Ultralytics COCO 預訓練權重，將 200×200 影像上採樣至 imgsz=640 訓練 100 epochs（fliplr=0.5, flipud=0.5, mosaic=1.0, close_mosaic=15, hsv_v=0.3, scale=0.4, patience=25）。
  • Faster R-CNN ResNet50-FPN-v2（雙階段 Anchor-based）：使用 Torchvision COCO_V1 預訓練權重，透過 FPN 多尺度金字塔（P2–P6）搭配 RPN 與 RoIAlign 進行兩階段邊界修正，設定 min_size=600, max_size=800、AdamW(lr=1e-4, weight_decay=1e-4)、CosineAnnealingLR(25 epochs) 與混合精度訓練。

3. IoU、Confidence Threshold、NMS 機制與超參數敏感度分析

  • IoU（Intersection over Union = 0.5）：定義預測框與 Ground Truth 之重疊比例。IoU ≥ 0.5 為 True Positive 門檻，類別錯誤、IoU < 0.5 或同一 GT 之重複預測皆計為 False Positive。
  • Confidence Threshold（提交設定 0.01 vs. 產線警報 0.25–0.50）：由於 Slide-31 Pascal VOC mAP@0.5 積分整條 Precision-Recall 曲線，過高門檻會提前截斷高召回尾部而壓低 AP；因此正式 stage3_detect.py 採用 conf = 0.01（平均每張 12.26 框，遠低於 100 框上限），完整保留 PR 面積達成 mAP@0.5 = 0.7866（Recall = 0.9454，Precision = 0.1831）。於實際產線告警與視覺化時，則將顯示／警報門檻調高至 conf = 0.25–0.50，使 Precision 由 0.183 大幅拉升至 0.504–0.617（F1 = 0.634–0.703）。
  • NMS IoU Threshold（選定 0.5）與 Anchor vs. Anchor-free 機制比較：單階段 YOLO11 採 Anchor-free DFL 頭直接回歸中心到四邊距離，省去手動 Anchor 尺度調校並達成極快推論；雙階段 Faster R-CNN ResNet50-FPN-v2 則透過多尺度 RPN Anchors 先過濾前景候選框再經 RoIAlign 進行第二次精細邊界回歸，於瀰漫弱紋理類別上展現顯著優勢（crazing AP = 0.5093 vs. YOLO11s 0.3797；rolled_in_scale AP = 0.6692 vs. YOLO11m 0.5961），並以 NMS IoU = 0.5 抑制同一目標冗餘框。

Slide-22 核心問題回答與工程討論：
  1. 模型漏掉了哪些 defect？與物件大小、紋理或背景相似有關嗎？ 漏檢（FN）主要出現在面積偏小的 inclusion（驗證集中位寬只有 23 px，例如 VAL_0067 角落 308 px² 的小夾雜）以及對比度很弱的 crazing／rolled_in_scale，當瑕疵本身幾乎融入熱軋背景紋理時特別容易漏掉。
  2. Bounding Box 為什麼偏移或過大？IoU 不足的原因是什麼？ 像是 pitted_surface 與 crazing 屬於大面積散佈型紋理，標註框邊界本身就不像剛體物件那麼明確。從 VAL_0173 可以直接看到，Ground Truth 標成左右兩個相鄰的 pitted_surface 框，但模型把它們合併預測成一個涵蓋整張圖的大框（IoU = 0.500 未達標準），這類合併或只框到核心區域的情況是 Poor Localization 的主因。
  3. 調整 Confidence Threshold 後，Precision 與 Recall 如何改變？ Threshold 從 0.01 提高到 0.50 時，Precision 一路從 0.183 升到 0.617，Recall 則從 0.945 降到 0.816。若產線擔心漏檢，threshold 設在 0.20–0.25 比較合適；若要減少誤報則可拉高到 0.40–0.50。
  4. 模型複雜度與精度的取捨如何？更大的 Detector 是否真的值得？ 這裡有很明顯的取捨：Faster R-CNN R50-FPN-v2 雖然拿到最高的 mAP@0.5 = 0.7866，但參數量達 43,281,778（權重 165.5 MB），比較適合高算力、重視極致召回率的品管複檢站；若產線端受限於記憶體與硬體資源，改用 YOLO11m（20,057,634 參數 / 38.7 MB）或 YOLO11s（9,430,114 參數 / 18.3 MB）會輕量許多。另外也觀察到在 VAL_0250 等案例中，有些所謂 False Positive 其實是鋼板上原本就存在、但未標註到的細微刮痕。
  5. 若部署到工廠，你會使用這個 Detector 嗎？為什麼？ 會，但會依產線工位做搭配。 因為單標籤分類沒辦法處理一張圖出現多種瑕疵的情況（本資料集共有 104 張複合瑕疵圖），Detector 才能同時回答「是什麼」跟「在哪裡」。精檢站用 Faster R-CNN R50-FPN-v2 確保 crazing 與 rolled_in_scale 不漏接；資源受限的邊緣工位則可部署輕量的 YOLO11m。
